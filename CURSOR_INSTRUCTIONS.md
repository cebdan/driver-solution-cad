# Инструкции: Минимально работающее GUI

## Архитектура GUI

### Ядро системы

**Solution Manager GUI** - главное окно + терминал
- Окно Solution Manager для управления решениями
- Терминал для команд и вывода информации

### 2D Solution - группа окон

При запуске 2D Solution открывается группа окон. **ВАЖНО: Все окна полностью независимы!**

1. **Окно отображения построений (главное окно)**
   - 3D окно, но запускается видом сверху (top view)
   - Отображение всех построений
   - Интерактивное взаимодействие с объектами
   - **Независимое окно** - закрывается/сворачивается только само

2. **Окно выбора группы инструментов**
   - Выбор категории инструментов (линии, окружности, примитивы и т.д.)
   - **Независимое окно** - закрывается/сворачивается только само

3. **Окно инструментов**
   - Список доступных инструментов выбранной группы
   - Активация инструментов
   - **Независимое окно** - закрывается/сворачивается только само

4. **Окно параметров**
   - Параметры выбранного инструмента
   - Редактирование значений
   - **Независимое окно** - закрывается/сворачивается только само

5. **Окно переменных**
   - Список всех переменных документа
   - Редактирование значений переменных
   - Создание/удаление переменных
   - **Независимое окно** - закрывается/сворачивается только само

6. **Окно слоев**
   - Управление слоями документа
   - Включение/выключение слоев
   - Переименование, создание, удаление
   - **Независимое окно** - закрывается/сворачивается только само

7. **Окно истории построения**
   - Список операций построения
   - Undo/Redo
   - Навигация по истории
   - **Независимое окно** - закрывается/сворачивается только само

8. **Окно отображения в виде нодов**
   - Визуализация графа зависимостей
   - Отображение связей между Solution
   - Редактирование через ноды
   - **Независимое окно** - закрывается/сворачивается только само

---

## КРИТИЧЕСКИ ВАЖНО: Независимость окон

### Правила независимости

**Каждое окно должно быть полностью независимым:**

1. **Никаких общих дескрипторов**
   - Каждое окно имеет свой собственный SDL_Window
   - Каждое окно имеет свой собственный SDL_GLContext
   - Каждое окно имеет свой собственный ImGuiContext
   - Никаких shared_ptr или глобальных указателей на окна

2. **Никаких общих вызовов**
   - Каждое окно обрабатывает свои события самостоятельно
   - Каждое окно рендерится независимо
   - Каждое окно управляет своим жизненным циклом
   - Никаких функций типа "закрыть все окна" или "свернуть все окна"

3. **Независимое закрытие/сворачивание**
   - Закрытие одного окна НЕ закрывает другие
   - Сворачивание одного окна НЕ сворачивает другие
   - Каждое окно работает автономно

4. **Связь только через данные**
   - Окна общаются только через общее состояние данных (Solution)
   - Никаких прямых ссылок между окнами
   - Изменения данных автоматически обновляют все окна через систему Solution

## Технические требования

- GUI фреймворк: ImGui + SDL2 (уже используется)
- **Каждое окно - полностью независимое:**
  - Свой SDL_Window
  - Свой SDL_GLContext
  - Свой ImGuiContext
  - Свой обработчик событий
  - Свой цикл рендеринга (или общий цикл, но без зависимостей)
- **Связь между окнами:**
  - ТОЛЬКО через общее состояние данных (Solution)
  - Никаких прямых ссылок между окнами
  - Никаких общих дескрипторов
  - Никаких общих вызовов
- Интеграция с существующими классами Solution
- 3D окно использует OpenGL для рендеринга

## Примечания

- Минимально работающее = окна открываются, можно взаимодействовать
- Не требуется полная функциональность сразу
- Важна архитектура и структура окон
- **КРИТИЧЕСКИ ВАЖНО: Каждое окно полностью независимо - никаких глюков с зависимостями!**
- Окна общаются только через данные Solution, не через прямые вызовы
