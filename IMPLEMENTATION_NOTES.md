# Заметки по реализации

## Общая архитектура проекта

### Микроядро Solution
- Абстрактный класс `Solution` - основа всей системы
- Все компоненты интегрируются через `Solution`
- Поддержка истории построения (Construction History)
- Система нодов для скриптов
- Интеграция с XTD для GUI
- OpenGL 2.1 для 3D рендеринга
- Обмен данными между Solution объектами

### Основные классы
- `Solution` - абстрактный базовый класс
- `Value` - класс для работы с различными типами данных (int, double, string, bool, pointer)
- `CS` - система координат (x, y, z, a, b, c)
- `Point2D` - 2D точки с поддержкой координатных систем
- `Point3D` - 3D точки с поддержкой координатных систем
- `SolutionDocument` - абстрактный класс для документов
- `Document2D` - реализация 2D документов
- `StartWindow` - главное окно приложения
- `TerminalWindow` - окно терминала для команд

## GUI Framework (XTD)

### Установка
- Используется библиотека `xtd` для кроссплатформенного GUI
- Установка через CMake из `/usr/local/cmake`
- Зависимости: wxWidgets (для macOS)

### Реализация меню
- Меню создается через `xtd::forms::main_menu` и `xtd::forms::menu_item`
- Важно: `menu_item` объекты должны быть членами класса, чтобы не уничтожаться преждевременно
- Меню привязано к форме через `form.menu(main_menu)`

### Окно "Solution manager"
- Заголовок: "Solution manager"
- При закрытии окна (красная кнопка) - окно скрывается, а не закрывается
- Меню "Manager" остается доступным даже когда окно скрыто
- Закрытие приложения: File → Quit или Cmd+Q

## Проблемы и решения

### Проблема: Меню исчезает при закрытии окна
**Решение:** Использовать статические объекты меню, которые остаются в памяти даже когда окно скрыто. Меню создается в `main()` как статические переменные.

### Проблема: Cmd+Q не работает
**Решение:** Создан класс `close_app` с функцией `close()`, которая использует `std::exit(0)` для принудительного закрытия приложения. Также добавлен обработчик `key_down` на форме для перехвата Cmd+Q.

### Проблема: Красная и зеленая кнопки окна не скрываются
**Что пробовали (НЕ РАБОТАЕТ):**
1. Использование `minimize_box(true)` и `maximize_box(false)` в xtd - не скрывает кнопки
2. Функция `hide_close_button_by_title()` - поиск окна по названию и изменение `NSWindowStyleMask`
3. Функция `hide_close_button_all_windows()` - применение ко всем окнам
4. Функция `force_hide_close_buttons()` - принудительное скрытие
5. Делегат окна `SolutionManagerWindowDelegate` - перехват событий `windowDidBecomeKey` и `windowDidUpdate`
6. Множественные попытки с задержками (до 30 попыток с задержками до 200ms)
7. Вызов функции до показа окна, после показа, в событиях `handle_created` и `visible_changed`

**Текущий статус:** Кнопки все еще видны. Возможные причины:
- xtd может создавать окно не через стандартный NSWindow
- Окно может создаваться в другом потоке
- Стиль окна может переопределяться после установки
- xtd может использовать другой механизм управления кнопками

**Файлы с реализацией:**
- `src/macos_window_utils.mm` - нативный код для macOS
- `include/macos_window_utils.h` - заголовочный файл
- `examples/simple_gui_working.cpp` - основное приложение

**Что нужно попробовать в будущем:**
1. Получить прямой доступ к нативному NSWindow через xtd API (если доступно)
2. Использовать метод swizzling для перехвата создания окна
3. Создать окно напрямую через NSWindow вместо xtd::forms::form
4. Использовать категорию NSWindow для переопределения стиля
5. Проверить документацию xtd на предмет специальных свойств для управления кнопками

## Важные замечания

1. **Меню должно быть статическим** - иначе исчезает при скрытии окна
2. **Закрытие приложения** - использовать `close_app::close()` вместо `application::exit()`
3. **Разные окна - разные стили** - не применять единый стиль ко всем окнам
4. **xtd API** - может отличаться от стандартного macOS API, нужно проверять документацию
